# Specification and Current Limitations

## Purpose and Supported Build

Local add-on for official Minecraft Bedrock on Windows. The C# launcher verifies the game and prepares to load the custom C++ module. The module modifies only local controls and rendering; it is not a replacement client. This repository maintains an auditable implementation of Zoom and local rendering add-ons that can be built from the included source without third-party binary clients or modifications to the server or saved world.

The only supported package is `Microsoft.MinecraftUWP_1.26.5203.0_x64__8wekyb3d8bbwe`. Other versions are unsupported, and the launcher must reject them before installing hooks.

## Feature Scope

| Feature | Control | Behavior and verification status |
| --- | --- | --- |
| Zoom | T (hold), mouse wheel | Local FOV with a transition, restored when the key is released, Esc is pressed, focus is lost, or the active screen leaves gameplay. The uniquely verified mouse sensitivity option is temporarily adjusted for Zoom, interpolated from the current Minecraft value toward `MouseSensitivity` at 1° FOV, and restored only while the same owner remains bound to the same value address and the option still contains the value written by the module. Cumulative GameInput mouse coordinates remain unchanged. Default T Zoom activation, sensitivity-target validation, and restoration were checked in a local test world. Response across FOV levels, wheel behavior, and desktop mouse response still need a dedicated in-game check. |
| Always day | F6 | Keeps the local sun overhead at noon, the moon below the horizon, and the sky in its daytime phase without sunrise/sunset transitions. Changes only profiled temporary rendering inputs; world time continues normally. The user reported incorrect/moving celestial position in Fancy graphics (issue #22). Profile v5 covers the shared rotation and camera colour paths and passes complete native day-cycle and restoration tests; its final visual result awaits an in-game retest. |
| Nametag | F7 | Own name in both third-person views, including hidden HUD; uses the original renderer and depth testing for both text and background. Both cameras with F1 and F7 were verified in a local game. |
| Status indicator | F9 | Show or hide the local indicator. |
| Safe detach | F10 | Restore modified values and hooks, then detach the module. Restoration must not be forced if code has been modified by another party or a bridge is still running. |
| Full Bright | F8 | Changes temporary parameters of the standard local light texture, not gamma, player state, or saved lighting. The user confirmed it works; other rendering modes and interaction with Always day have not been verified. |
| FPS counter | `[fps_counter] enabled`, `font_size` | Bottom-left FPS display based on calls to the supported build's game update function, sampled once per second. Larger white Minecraftia/default Minecraft text on a rectangular black background with 65% opacity. Enabled by default; font size is configurable from 12 to 48. In-game appearance and live toggling await verification. |

Zoom values are configured in `[Zoom]` and feature shortcuts in `[Shortcuts]` in `config\bedrock-toolkit.ini`; the build script installs it next to the launcher only when no configuration exists, preserving existing user settings. Defaults are first-person FOV 25, third-person FOV 29, transition duration 75 ms, mouse sensitivity 45, and Zoom key T. `MouseSensitivity` uses Minecraft's 0–100 slider scale as the target at the minimum Zoom FOV of 1 degree; the module converts it to the normalized game option and interpolates from the live value based on FOV. Removing `bedrock-toolkit.ini` next to the launcher resets settings to defaults; the legacy `Fov` setting remains a fallback for both perspectives. All shortcuts must be supported and distinct. If the file or a setting is missing, the launcher and module use their defaults. If sensitivity, FOV, or camera perspective cannot be safely identified, the module must not attempt a blind write.

Always day and Full Bright start enabled after their rendering profiles are verified. Nametag starts enabled once valid camera options are available. Their configured shortcuts toggle them off and on. Zoom preparation starts automatically, but Zoom remains hold-to-use as described above.

Nametag's `[nametag] show_when_hud_hidden` setting defaults to `true` and accepts only `true` or `false` (case insensitive, surrounding whitespace allowed). With `true`, an enabled Nametag can bypass native HUD suppression only for the local player's name in a verified third-person camera. Other actors and hovered-object labels remain suppressed. First person, unavailable camera settings, F7 off, or `false` retain native HUD suppression. Preserve the native in-game player-name preference and other rendering restrictions; never modify the HUD option, player flags, or persistent game objects. Configuration changes require restarting the module.

Both setting values, both third-person cameras, first-person suppression, F7 toggling, and restoration of all five Nametag patches with F10 were checked in a local game. Hidden-HUD occlusion behind world geometry and suppression of named non-local actors still need dedicated visual checks; depth selection and actor filtering are covered by isolated tests.

The FPS counter defaults to enabled. Its `[fps_counter] enabled` setting accepts `true` or `false`, ignoring case and surrounding whitespace; missing uses the enabled default and invalid values disable it. `font_size` accepts integers from 12 through 48, with missing or invalid values using 28. These settings reload approximately every 500 ms; other configuration remains restart-only. Count calls to the verified `MinecraftGame` update function and calculate FPS over one-second sampling intervals; do not substitute the FOV option or another configured value. The counter is independent of the F9 status indicator, is click-through/non-activating, and appears only during foreground gameplay, including hidden HUD. Use installed Minecraftia or privately load the game's own Mojangles font; hide the counter if neither is available. Configuration polling, font loading, and counter rendering run on a separate thread, not the keyboard-hook owner or game input callbacks. Safe detach must wait for that thread to exit and release its overlay/font resources. The update hook must be validated against the supported PE profile and restored using the same ownership and callback-drain safeguards as other game hooks.

All module shortcuts require a foreground game window and a verified gameplay screen (`hud_screen`, `f1_screen`, `f3_screen`, or `zoom_screen`). Chat, menus, text entry screens, and unknown or unreadable screen state must leave keyboard and wheel input available to the game. Only stable native non-interactive `debug_screen` and `toast_screen` overlays may be skipped. The independently profiled native `cubemap_background_screen` may also be ignored, only at the bottom of the shared game stack; it can never establish gameplay in the player stack. Transitioning screens deny shortcuts, including chat while it is closing. A key held outside gameplay must be released before it can activate a module shortcut after returning to gameplay. Screen discovery must verify the supported native profile and find exactly one valid client; incomplete or ambiguous discovery must deny shortcuts. This is a screen allowlist, not per-character or chat-open-key tracking.

The former default C Zoom shortcut and F6–F10 shortcuts were verified in a local single-player world with this screen profile, including chat typing, returning to gameplay, and safe detach. Default T Zoom activation, unique FOV/sensitivity discovery, and restoration were also verified in a local test world. Live sensitivity response across FOV levels and wheel adjustment still need an in-game check. Other text entry screens, configured letter shortcuts, and holding a shortcut across a screen transition remain covered by isolated tests and require separate in-game verification.

## Security and Implementation Requirements

- Before any write, verify the exact package, PE identity, and complete original instructions with their relevant context. Reject the target on any mismatch, ambiguity, or read error.
- Do not treat FOV, sensitivity, or other heap addresses from a single session as stable identities. Find the correct named object and verify its structure, range, and uniqueness.
- Limit hooks to verified local input or rendering paths. Do not modify the server protocol, world time, saved world, player attributes, gamma, or persistent game objects.
- Prepare and verify installation of multiple patches as a coordinated operation. During restoration, compare both the installed patch and the expected original bytes; never overwrite another party's change. Before freeing bridge memory, wait for active callbacks to finish and verify game-thread instruction pointers. If restoration is unsafe, leave the module loaded and retry it.
- Before using an external package, verify its original source, version, license, build steps, and transitive dependencies. Prefer pinned source code and local builds. If its use is necessary, explicitly obtain the user's approval first, explain why it is required, and clearly describe identified risks and impacts; do not add or use the package without approval. MinHook source with its own license is included in `GameMod\vendor\minhook`. Do not add unknown or precompiled DLLs, third-party injectors, automatic downloads or updates, telemetry, or network communication by the add-on.
- Use only in a local single-player world. The project cannot reliably detect the game mode; multiplayer is unsupported.

## Build and Verification

Requirements and the build command are documented in [README.md](README.md). Tests can verify emitted bridges, registers, patching, and restoration against synthetic memory; by themselves, they do not establish behavior or visual results in a live game.

Read-only diagnostic tools for this build are in [diagnostics/](diagnostics/README.md). Reference RVAs and persistent findings for troubleshooting and future porting are in [FINDINGS.md](FINDINGS.md); the exact bytes for the supported profile remain in the source headers.

Compatibility claims apply only to the listed build. Multiplayer, other versions, dimensions, and graphics modes are not designated as supported. After changing the input path or rendering profile, distinguish successful builds, automated tests, and practical in-game verification again.

The gameplay/Zoom stutter changes (issue #30) and low-FOV sensitivity handling (issue #50) pass isolated transition-timing, sensitivity compare-and-swap/restoration, asynchronous diagnostic snapshots, blocked-writer shutdown, pending-restoration diagnostics, message-hook ownership, and input-aware wait tests. Sprint-jumping, camera movement at FOV 1, Zoom transitions in both directions, wheel adjustments, and screen/focus changes still require an in-game retest; automated checks do not establish smooth live frame pacing.
